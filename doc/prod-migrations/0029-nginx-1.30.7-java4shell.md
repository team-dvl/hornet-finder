# nginx 1.30.7 et contournement Java4Shell (`main` fd7e74e → `hotfix/1.6.1`)

**À exécuter depuis le worktree prod (`/home/debian/hornet-finder`).**

## Périmètre
- `docker-compose.{prod,dev}.yml` : image `nginx:1.29.0` → `nginx:1.30.7` (services `nginx` et `nginx-certbot`). Corrige les cinq failles « nginx2root » du 2026-11-18 (CVE-2026-123007, -123633, -123634, -121810, -113425). La config de prod n'active ni HTTP/2, ni HTTP/3, ni proxy mail, ni `resolver` : exposition pratique nulle, mais l'image avait plusieurs versions de sécurité de retard.
- `docker-compose.{prod,dev}.yml` : variable `JAVA_OPTS_APPEND=-XX:-UseBASE64Intrinsics` sur Keycloak, contournement officiel de Java4Shell (CVE-2026-114938, https://github.com/keycloak/keycloak/issues/55293). Le CPU du serveur (Xeon E5-1620 v2) n'a pas AVX-512 VBMI : le chemin de code fautif n'est pas actif, le drapeau est une garantie si le matériel change. **Aucune image Keycloak corrigée n'existe au 2026-11-19** : à retirer quand l'image avec un OpenJDK corrigé sera publiée (nouveau bump de `auth/Dockerfile`).

Ne change pas : backend, frontend, base de données, `.env`, volumes, realm, `auth/Dockerfile` (Keycloak reste en 26.8.1).

**Impact utilisateurs** : redémarrage de nginx (coupure de quelques secondes du site et de l'API) et de Keycloak (connexion impossible quelques secondes). Aucune migration de schéma.

## Prérequis
- Notes 0027 et 0028 déjà appliquées.
- Accès à Docker Hub depuis le serveur (pull de `nginx:1.30.7`).
- Validation faite en dev (`nginx -t` avec la nouvelle image, démarrage de Keycloak avec le drapeau).

## Étapes
1. `git merge --no-ff v1.6.1` (le tag est créé sur la branche `hotfix/1.6.1` ; `main` ne reçoit que des points de release).
2. `docker compose pull nginx` puis `./deploy.sh -s nginx` : **redémarrage** du conteneur (un `reload` garderait l'ancien binaire en mémoire).
3. `./deploy.sh -s auth` (recrée Keycloak avec la variable).

## Vérification
- `./status.sh` : services, certificats et endpoints OK.
- `docker exec hornet-finder-nginx-prod nginx -v` : `nginx/1.30.7`.
- `docker exec hornet-finder-keycloak sh -c 'jcmd $(pgrep -f QuarkusEntryPoint | head -1) VM.flags -all | grep -F UseBASE64Intrinsics'` : `bool UseBASE64Intrinsics = false`.
- `https://velutina.ovh` : connexion Google, connexion mot de passe + OTP (admin), rafraîchissement de session. `https://auth.velutina.ovh/realms/hornet-finder/.well-known/openid-configuration` répond 200.

## Rollback
`git revert -m 1` du merge de `v1.6.1` (ou retour du tag `v1.6.0`), puis `./deploy.sh -s nginx` et `./deploy.sh -s auth`. Aucune donnée n'est touchée : pas de snapshot nécessaire.
